Why manual allocation breaks down

Assigning students to classes is a genuine multi-criteria decision problem. A school needs to balance academic levels, behaviour, gender distribution, language-support needs, individual learning plans, friendships and incompatibilities, and operational constraints — while still producing something school leadership can review and trust. Done by hand, it consumes real staff time and rarely produces the same result twice.

Under the hood: a clean, layered architecture

A local Flask application with clear separation between the web layer, data extraction, the optimisation engine and output generation — deliberately simple for a single-school deployment.

def clean_score(x) -> Optional[int]:
    """Convert a cell to an integer score between 1 and 5.

    Returns an int in [1,5], or None if the cell is empty.
    Raises ValueError if the parsed number is out of range —
    invalid scores must never enter the optimiser silently.
    """
    if pd.isna(x):
        return None
    try:
        value = int(float(x))
    except (ValueError, TypeError):
        return None

    if value < 1 or value > 5:
        raise ValueError(f"Invalid score: {x}")
    return value

A weighted, multi-criteria local search

Every candidate allocation is scored by a single cost function — a weighted sum of penalties across 19 criteria. Lower is better; there is no single “correct” answer, only better and worse trade-offs.

Order by placement difficulty→ Greedy construction→ Local search: moves→ Local search: swaps→ Score & keep best of N
Mean-based balance (behaviour, academic scores)
C = w · (mk − m*)²
Proportion-based balance (gender, learning plans)
C = w · (pk − p*)²
Count-based dispersion (EAL, new students)
C = w · (nk − n*)²

Shown: 8 of 19 configurable criteria, each adjustable from 0 to 20 in steps of 0.5. Weights are relative coefficients, not probabilities — a higher weight increases influence, it does not guarantee the criterion is fully satisfied.

What building this proved

This project was scoped, built, deployed and supported end-to-end, solo, as an independent (auto-entrepreneur) engineer — directly for a school that needed a working tool, not a prototype.

Backend & data engineering

  • Python, Flask, background worker threads

  • Input validation that fails loudly, never silently
  • Structured logging & JSON-based state management

Algorithms & systems design

  • Multi-criteria weighted cost-function design
  • Greedy construction + local-search heuristics
  • Layered architecture: extraction / allocation / output
